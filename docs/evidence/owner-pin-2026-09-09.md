# Owner PIN is separate from login password — 9 September 2026

## Confirmed defect and implementation

Security settings called its form “Change PIN” but submitted `/auth/change-password`, accepted a six-character new password, changed `passwordHash` and left the four-digit `pinHash` untouched. Success copy also falsely combined the two credentials.

The form now submits `/auth/pin/set` with a four-digit PIN, matching confirmation and the owner's current login password. The endpoint requires owner role and freshly verifies that password. Its transaction compares the previously verified credential versions before writing, updates only `pinHash`, and commits the required security audit atomically. The login password is unchanged. First PIN setup follows the same password-approval requirement. The current device's offline screen-unlock enrollment is removed only after a confirmed PIN change, with instructions to enroll it again if wanted.

English/Hindi labels distinguish the login password from the new owner PIN. The form clears secrets on close, disables submission/closing during the mutation, retains server failures visibly, and never claims a PIN change from an unconfirmed response. Non-owner users cannot use the form.
