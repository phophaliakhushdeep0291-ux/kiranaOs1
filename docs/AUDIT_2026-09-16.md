# Bug fixes and interface audit — 16 September 2026

Scope: an initial repository audit, full frontend validation, backend test suite, and live sign-in/password-recovery UI checks. Based on `cf0346be`, with changes in `work/bugfix-interface-audit`. This is a focused improvement pass, not a claim that every shop workflow has been audited.

## Fixed findings

| Finding | Previous behavior | Change and evidence |
|---|---|---|
| Post-login destinations were trusted without validation | The storage helper accepted external URLs, auth-page loops and future timestamps. A destination containing a fragment reaches full browser navigation after login. | Validate both stored and new destinations; allow internal routes only, preserve legitimate query/hash payloads, enforce finite timestamps within the five-minute window. New regression cases reproduced 11 failures before the fix. An external writer/caller is a precondition for an unsafe destination; no remote exploit was established. |
| Hindi authentication displayed English validation and recovery instructions | Submitting empty login fields in Hindi displayed English errors; recovery/reset pages had no language control. | Shared schemas return translation keys, so errors use the current language. Added English/Hindi recovery copy and language controls. Live browser reproduced the old login errors and verified translated errors after the change. |
| Whitespace passed identifier validation | Three spaces satisfied the minimum length and could start an avoidable login/recovery request. | Trim identifiers before validation; also normalize the shop-selection replay. Preserve passwords exactly, including intentional spaces. Behavioral tests cover both forms and password confirmation. |
| Device replacement could finish after returning to sign-in | The replacement request disabled device selection but left the Back action and PIN editable while the request could still authenticate. | Disable the Back action and PIN during replacement, expose selected-device state to assistive technology, and guard repeat calls. Reviewed in code; a live owner-PIN/device-replacement transaction was not exercised in this pass. |

## Interface changes

- Added a keyboard-accessible, 44px show/hide password button on sign-in.
- Associated validation errors with inputs and announced errors/statuses to assistive technology.
- Added username/current-password/new-password autocomplete metadata and disabled automatic capitalization for identifiers.
- Reduced nested padding on small sign-in screens to leave more room for fields.
- Added language controls to recovery/reset and clearer instructions for incomplete reset links.
- Recovery confirmation now says a link is sent only if the account supports recovery; it also points users to the spam folder.

## Suggested next work

These priorities come from this repository's architecture, roadmap and release documents; they are proposals, not new features implemented in this pass.

1. **Complete a real counter acceptance flow.** Run cash + UPI + udhar sales, return, purchase receipt, offline restart and two-device sync against an isolated shop. Reconcile bills, stock and ledgers after each step. Retain evidence against the exact release candidate, then run the PostgreSQL/worker/restore gates described in `RELEASE_GATE.md`.
2. **Measure and simplify the busiest mobile flows.** Use billing, product search and udhar collection with a shopkeeper; count taps and time-to-completion at 320–430px. Make the common action easy to reach and move infrequent controls out of the way, while retaining the existing owner approvals and offline behavior.
3. **Test sync recovery as a user task.** The app already has a detailed Sync Status page. Check whether a cashier can distinguish a locally saved sale, a pending upload and a conflict, and recover without duplicate billing. Improve copy/actions based on that test rather than adding another status dashboard.
4. **Finish provider and printer proof.** Verify configured recovery email/receipt delivery and the two supported receipt printers. The existing backlog still requires signed Windows installation and physical paper-out/retry/no-duplicate evidence.
5. **Plan the remaining paise-storage migration.** The architecture explicitly records Float storage alongside partial BigInt shadow fields. Inventory the remaining aggregate paths and migrate with reconciliation and rollback evidence before making stronger accounting guarantees.

Several requested-sounding features already exist: low-stock reorder suggestions, supplier ledgers, held bills, customer timelines, loyalty, split payments and daily closing. Improve and verify those flows before building duplicates.
